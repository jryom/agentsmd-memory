# Lifecycle memory prototype

Experimental, opt-in, no release required. Existing file-only behavior remains the default. Tools still never write files: the agent applies proposed edits, visible in your working tree.

This prototype needs no additional libraries. Zero dependencies is not a design constraint for future work; adopt libraries when they meaningfully improve retrieval, validation, or storage correctness.

## Try it in a project

Use this branch's local `src/index.mjs` as the MCP server, as described in [development](development.md). The installed npm package does not include this prototype. Native plugin registration uses the same tools, but live client behavior still needs testing.

1. Keep durable user rules and critical constraints in the existing entry point.
2. Create `.agents-memory.json` beside that entry point (or at the Git root):

```json
{
  "version": 1,
  "facts": [
    {
      "id": "migration-api",
      "fact": "Use the supported migration API, not direct database edits.",
      "scope": "database migrations",
      "evidence": ["docs/migrations.md#supported-api"],
      "reason": "Direct edits bypass consistency checks.",
      "status": "candidate",
      "protected": false
    }
  ]
}
```

This is an illustrative fact, not a claim about this repository. Replace it with evidence-backed project knowledge, or begin with an empty facts array. Stable ids survive wording changes. Evidence can reference code, maintained docs, or an explicit user decision; do not invent citations. Supported states: `candidate`, `active`, `archived`.

3. Add `.agents-memory.local.json` to the project's Git ignore rules before recording feedback. For a local-only trial, use `.git/info/exclude` instead. Track the fact store, not telemetry.
4. Add a short discovery rule to the entry point:

> Lifecycle memory lives in `.agents-memory.json`. At task start, use `memory_recall` with the current task. Verify evidence before applying retrieved facts. Record `memory_feedback` only when a verified fact materially helped or current evidence contradicted it. Use `memory_review` for requested maintenance.

5. Call `memory_recall` with `cwd` and a `query`, for example `database migration`. It returns up to five lexical matches. `memory_save`, `memory_forget`, and `memory_review` now return sidecar-specific editing guidance.
6. After a fact helps, call `memory_feedback` with its `id`, an opaque stable `task` id, and `outcome: useful`. Contradictions use `outcome: contradicted` and require correcting the fact, not merely recording a negative signal.

Local feedback shape:

```json
{
  "version": 1,
  "signals": [
    {"id": "migration-api", "task": "task-42", "outcome": "useful", "at": 1800000000000}
  ]
}
```

`at` is epoch milliseconds, generated by the tool. The agent replaces an existing id/task signal rather than accumulating repeated votes. No tracked usage timestamps. Different clones have independent telemetry; shared facts still travel through Git.

## Retention and cleanup

- Relevant term matches dominate ranking. Distinct useful tasks add a capped boost; freshness adds a smaller boost that fades over 90 days. Archived facts never appear. Retrieval alone gives no boost.
- Every retrieved fact needs verification. Contradictions are flagged, not hidden: hiding a warning could lose an important correction.
- New uncertain facts start as candidates. Evidence supports promotion to active; popularity does not establish truth.
- Review unproven candidates first. Archive confirmed obsolete, superseded, or assessed low-value facts with a reviewable `archiveReason` field. Lack of use alone is not enough.
- Protected facts cannot be archived without explicit approval. Critical rules stay in the entry point, where lexical retrieval cannot accidentally omit them.
- Archives remain in the store for inspection and Git diffs. No background cleanup or automatic deletion.

To disable: remove the entry-point discovery rule and move the sidecar out of the discovery path. Preserve important guidance in the entry point first.

## Evaluation before adopting

Try several unrelated tasks, one repeated gotcha, one contradicted fact, and one rare safety rule. Review selected facts and Git diffs. Check whether facts actually prevented mistakes and whether feedback/maintenance overhead was worthwhile. Restart the local server when switching code versions.

Limitations: lexical matching, at most five results, whole-store reads, agent-applied feedback and cleanup, no concurrent-write protection, no semantic deduplication, no automatic evidence checks. Freshness is a ranking hint, not a correctness guarantee. Agent behavioral evaluation and live client installation remain unverified. This prototype establishes a reviewable lifecycle; it is not an autonomous memory database.
